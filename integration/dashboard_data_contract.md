**Project**: AI-Based Intelligent Vehicle Monitoring and Traffic Violation Detection System  
**Document**: Final Data & Integration Contract for Member 3 (Dashboard / Frontend)  
**Authors**: Member 2 (NPR & Fine Estimation) in collaboration with Member 1 (Detection, Tracking & Violations)  
**Status**: Production-Ready / Final Verified Specification  
**Reference Video / Dataset**: `teammate_video` (1280×624 @ 30.0 fps, 413 frames, 179 tracked vehicles)

## 1. System Integration Architecture & Data Flow

The complete system pipeline processes traffic video through distinct, decoupled computer vision and rule-evaluation modules before exposing a **Unified Vehicle Record** to the dashboard and alert system:

```
                      [ Raw Traffic Video (.mp4 / .avi) ]
                                      │
                                      ▼
             [ Member 1: Vehicle Detection & ByteTracker (YOLOv8/v11) ]
                                      │
                         Emits: <stem>_tracks.csv
                                <stem>_vehicles.csv
                                <stem>_tracks.json
                                      │
              ┌───────────────────────┴───────────────────────┐
              ▼                                               ▼
[ Member 1: Violation Layers ]                [ Member 2: Plate Recognition (NPR) ]
 ├── Speeding (_violations.csv)                ├── Crop at best_frame_id
 ├── Wrong-Side (_wrong_lane_violations.csv)   ├── YOLOv8n Plate Detector (best.pt)
 ├── Lane-Change (_lane_change_events.csv)     ├── Multi-Variant Preprocessing (LAB/CLAHE)
 └── Tailgating (_tailgating_events.csv)       ├── EasyOCR Multi-Candidate Text Engine
              │                                └── Indian RTO / BH Syntax Validator
              ▼                                               │
[ Member 2: Fine Estimation Module ]                          │
 ├── Ingests all 4 violation summary CSVs                     │
 ├── Reads speed limit from _speed_meta.json                  │
 ├── Evaluates rules & overspeed delta (max_speed_kmh)        │
 └── Computes itemized breakdown & compounding                │
              │                                               │
              └───────────────────────┬───────────────────────┘
                                      ▼
                        ┌───────────────────────────┐
                        │   UNIFIED VEHICLE RECORD  │
                        │   (Per-Vehicle JSON/CSV)  │
                        └─────────────┬─────────────┘
                                      │
                     ┌────────────────┴────────────────┐
                     ▼                                 ▼
         [ Member 3: Web Dashboard ]       [ Email Alert Service ]
          - Interactive Overview Table      - Automated Violation Notice
          - Video & Evidence Playback       - Prototype Demonstration
          - Real-Time Analytics Charts      - Targeted Recipient: Author
          - Vehicle Detail Dossier
```

## 3. Identification & Composite Key Strategy

1. **Intra-Video Uniqueness**:
   - `vehicle_id` is an integer assigned by ByteTrack (e.g., `1`, `2`, `20`, `975`).
   - `vehicle_id` is unique **only within an individual video clip**.
2. **Cross-Video Global Identity**:
   - To avoid collisions when multiple video streams or historic clips are ingested, the system uses a **Composite Identifier**:
     $$\text{composite\_id} = \text{video\_id} + \text{"\_"} + \text{vehicle\_id}$$
     *Example*: `"teammate_video_20"`
3. **Invalid Track IDs**:
   - Detections with `vehicle_id = -1` (or $\le 0$) represent unconfirmed transient tracks and are strictly filtered out before dashboard presentation.
4. **Tailgating Follower vs. Leader**:
   - In `<stem>_tailgating_events.csv`, `follower_id` represents the offending vehicle (`vehicle_id`). `leader_id` is the front vehicle and is never penalized for tailgating.

## 6. Edge Cases & Missing Value Semantics

### A. Non-Violating / Compliant Vehicles
- `violations`: `[]` (empty list)
- `violation_count`: `0`
- `total_fine`: `0.0`
- `fine_breakdown`: `{}`
- `first_violation_frame`: `null`, `first_violation_sec`: `null`

### B. Missing / Uncalibrated Speed Values
- Speed is only computed when a vehicle's bounding box base satisfies $y \ge 268.0$ (calibrated zone).
- Vehicles outside this zone have `is_speed_measured: false`, `max_speed_kmh: null`, `avg_speed_kmh: null`, `speed_delta_kmh: null`.
- **Handling**: The system **never crashes** and does not invent speeds. Overspeeding penalties are safely skipped.

### C. Missing / Unreadable License Plates
- In the reference video, only **38% of vehicles (68/179)** meet the $\ge 5000\text{ px}^2$ legibility budget.
- For small, distant, or occluded vehicles: `plate_detected: false`, `plate_text: null`, `ocr_confidence: null`, `is_valid_indian_format: null`.
- **Dashboard Representation**: Display badge `"PLATE UNRESOLVED (LOW RES)"` rather than throwing an error.

### D. Multi-Violation Compounding
- When a vehicle triggers multiple violations (e.g. speeding + tailgating), `violations` contains all types, `fine_breakdown` itemizes each charge, and `total_fine` compounds them according to the configured policy (`"sum"` by default).
